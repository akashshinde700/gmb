## A. What the product is

WebSetu is a multi-tenant SaaS that builds and hosts local-business websites.
One Next.js 16 App Router application serves three things at once: the
platform's own marketing pages, the customer console, and every tenant's
published website (rendered at `/s/<slug>` and, for paying customers, on their
own domain via `src/proxy.ts`).

**Roles**

| Role | Reaches | Guard |
|---|---|---|
| Anonymous | `/`, `/blog`, `/developers`, `/login`, published tenant sites, `/api/plans`, `/api/site/[slug]`, lead + order + analytics beacons | per-route rate limits |
| `CUSTOMER` | `/onboarding`, `/dashboard/*`, `/api/**` scoped to their own business | `requireUser` + `requireBusiness` |
| `ADMIN` | `/admin/*`, customer provisioning, impersonation, plans, coupons, palettes, backups | `requireAdmin` |
| `RESELLER` | `/reseller`, the Builder API (`/api/v1/sites`) | hashed API key (`requireApiKey`) |
| Cron / root | `/api/internal/*` | `INTERNAL_TOKEN`, timing-safe, off when unset |

**Modules.** Onboarding wizard → AI content → site builder/editor → publish →
SEO + sitemap + JSON-LD → leads inbox → commerce (cart, orders, UPI QR) →
analytics → domains + DNS/hosting records → subscription/billing with GST
invoicing → admin console → reseller white-label + Builder API.

**Journeys traced end to end:** register → login → onboarding → generated site →
content CRUD → publish → public render → lead captured → lead in dashboard →
export CSV; and admin → customer list → provision → impersonate → plan change →
backup download. No journey was found broken in the paths exercised by the
suites above.

## B. Critical

### C1. The deployable build contained the live database and the server's `.env`

**File:** `next.config.ts` (`outputFileTracingExcludes`), `src/lib/uploads.ts`,
`src/app/api/admin/backup/route.ts`

**Problem.** `npm run build` produced a `.next/standalone` directory — the folder
that is uploaded to the server on every deploy — containing a copy of the
repository root:

```
$ ls .next/standalone
AGENTS.md  CLAUDE.md  GMB-PATCH-e67100a3.patch  HOSTING-BUNDLE-*.md  PUSH-INSTRUCTIONS.md
REVIEW-*.md  SCALE-*.md  TODO_code-reviewer.md  components.json  db  e2e
eslint.config.mjs  freemodels-api.json  marketing_content  prisma  public  scripts
src  tests  tools  tsconfig.json  worklog.md  .env      ← 199 MB, 35 entries
```

`db/` is the live SQLite database: scrypt password hashes, customer names,
phones and emails, leads, orders and payments. `.env` is the build machine's
environment file: `APP_SECRET` (the HMAC key every session token is signed
with), and on a production box `RAZORPAY_KEY_SECRET`, `SMTP_PASS` and
`HTTPSMS_API_KEY`.

**Why it matters.** The artifact is the thing that moves. It is scp'd, tarred,
uploaded, cached in CI, and occasionally mailed to a colleague. Shipping a
database of personal data and a signing key inside it is the same class of
mistake as committing them, with extra steps — and unlike a committed file,
nothing warns you. It was also 199 MB of upload for a Node server that needs
none of it.

**Root cause — three separate mechanisms, which is why it took three fixes.**

1. **The trace widened to the project root.** Next traces the files a route can
   read at runtime. Three reads have paths that cannot be resolved statically —
   `uploadsDir()` (an environment variable) in two places, and `os.tmpdir()` in
   the admin backup route — and the documented fallback for an unresolvable path
   is *include everything under the project root*. That is what put `db/`,
   `e2e/`, `marketing_content/` and the patch file into the artifact.
2. **The excludes only covered two routes.** `next.config.ts` had them keyed
   `"/api/upload"`; the matching really is `picomatch(key, { contains: true })`,
   so that key did cover `/api/uploads/[file]` — but it covered *nothing else*,
   and it was `/api/admin/backup` whose trace had the whole root in it. It also
   did not list `marketing_content/` or `*.patch`.
3. **`.env` was not a trace at all.** `next build` copies `.env` and
   `.env.production` into `.next/standalone` on purpose
   (`writeStandaloneDirectory` in `next/dist/build/index.js`), so the build
   machine's secrets ship inside the artifact no matter how clean the tracing
   is. Nothing reads it afterwards: `server.js` never calls `loadEnvConfig`, and
   the deploy path supplies configuration from outside —
   `scripts/deploy-swap.py` uploads the real `.env` to the app directory
   (line 174), inlines the runtime env into PM2 (line 90), and starts the
   server with `set -a && . ./.env && set +a` (line 236).

**Solution (implemented).**
1. `/* turbopackIgnore: true */` on the three affected filesystem calls, so the
   tracer stops following paths that are, by definition, runtime-only.
2. One `"*"` key in `outputFileTracingExcludes`, which matches every route, with
   the full list of repository material.
3. `scripts/strip-standalone-env.mjs` — removes `.env` and friends from the
   artifact during the build, with `KEEP_BUILD_ENV=1` as the documented opt-out
   for anyone who genuinely boots an artifact with a baked-in env file.
4. `scripts/check-standalone.mjs` — a build-fail check for `.env*`, `*.db`,
   `*.pem`, `.git`, deployment credentials and repository directories anywhere
   in the artifact — wired into `npm run build`, so the next dynamic read
   somebody adds cannot silently reintroduce this.

**Proof.**

```
$ ls -a .next/standalone          # before: 35 entries, .env + db/ + src/ + e2e/ + the patch
.  ..  .next  node_modules  package.json  public  server.js
$ du -sh .next/standalone
185M                              # was 199M
$ npm run build                   # ends with:
strip-standalone-env: removed .env from .next/standalone (runtime env comes from the environment).
check-standalone: .next/standalone is clean.
```

The artifact was then run as the deployment runs it — `node server.js` from
inside `.next/standalone` — and served `/`, `/login`, `/blog`, `/developers`,
`/s/sharma-electricals`, `/api/health` and `/api/plans` with 200s.

## C. High

### H1. The production build required an internet connection to Google

**File:** `src/app/layout.tsx`

**Problem.** The typeface was loaded with `next/font/google`, which downloads
from `fonts.googleapis.com` **at build time**:

```
Error: next/font: error: Failed to fetch Geist from Google Fonts.
If you are offline or behind a proxy, self-host the font with next/font/local…
> Build error occurred
```

**Why it matters.** `npm run build` is what produces the artifact that runs the
customer's website. A VPS behind an egress firewall, a CI runner without
internet, a Google outage, or a DNS hiccup on the build machine all make the
deploy fail — for a product whose entire promise is that a business's site stays
online. It is a build-time dependency on a third party for a font.

**Solution.** Vendor the two variable weights (117 KB total) into
`src/app/fonts/`, load them with `next/font/local`, and keep the SIL Open Font
License alongside them (`src/app/fonts/OFL.txt`, which is what redistribution
requires). Fallback stacks are declared explicitly for both families.

**Proof.** The build that failed before this change compiles in 19.8 s with no
network access:

```
✓ Compiled successfully in 19.8s
✓ Generating static pages using 1 worker (102/102)
```

### H2. A public, unauthenticated proxy to an undocumented third party

**Files:** `src/app/api/chat/route.ts`, `src/app/api/models/route.ts`,
`src/lib/freemodels.ts`, `freemodels-api.json`, `src/app/api/health/route.ts`

**Problem.** Three routes and a 12 KB config file implemented an integration with
`freemodels.pro` that no page, no script and no test in the repository ever
called:

- `POST /api/chat` — an **open proxy**. Anyone on the internet could send up to
  50 messages per request, ten requests a minute per IP, and have this server
  make the upstream call on their behalf.
- `GET /api/models` — the same service's model list, publicly.
- `GET /api/health` probed that upstream and reported it as `checks.freeModels`,
  i.e. as one of *this platform's* dependencies.
- `freemodels-api.json` is a config "reverse-engineered" from the site,
  including the exact `Origin: https://freemodels.pro` and
  `Referer: https://freemodels.pro/` headers the proxy sends to look like that
  site's own frontend.

**Why it matters.** Four separate problems wear one coat. An unauthenticated
proxy spends the platform's bandwidth and its IP's reputation on a stranger's
traffic. The health endpoint would have paged its operator because an unrelated
third party was down, which is worse than no health check. The config file
documents header spoofing of somebody else's service in a public repository.
And the platform's real AI stack — `src/lib/llm.ts` with its provider chain,
router and usage ledger — never touched any of it.

**Solution.** Removed all of it: both routes, the module, the config, and the
health probe. `src/app/api/health` now reports only dependencies of this
platform (database, mail configuration, SMS allowance).

**Proof.** `tests/api-smoke.mjs` gained a `No unauthenticated third-party
proxies` section asserting `/api/chat` and `/api/models` answer 404, plus a
health check asserting the third-party probe field is gone.

## D. Medium

### M1. The charting library loaded on every console screen

**Files:** `src/components/views/dashboard-view.tsx`,
`src/components/views/admin-view.tsx`

**Problem.** `recharts` — the single heaviest client dependency in the app — was
imported statically at the top of both console views. Those two files *are* the
consoles: `dashboard-view.tsx` is 5,400 lines covering fourteen tabs. So opening
`/dashboard/leads`, `/dashboard/builder` or `/admin/plans` downloaded a
charting library in order to draw an inbox, a form, or a table. There was no
`next/dynamic` call anywhere in the codebase.

**Why it matters.** It is paid on the slowest connection in the product's market
— a shop owner on 4G — on every navigation, for a library whose output appears
on exactly two screens.

**Solution.** `src/components/views/charts.tsx` holds the three charts; both
call sites pull them through `next/dynamic` with `ssr: false` and a skeleton of
the right height (so the lazy load introduces no layout shift). The legend dots
next to the customer chart moved from inline hex values to the equivalent
Tailwind classes (`bg-emerald-600`, `bg-amber-600`), which is also how the now
unused `CHART_COLORS` constant disappeared.

**Proof.** `npx tsc --noEmit` clean; build clean; the recharts import no longer
appears in either view (`git grep recharts -- src` returns only the comment
explaining why the module exists).

### M2. The scale proof was never executed by anything

**File:** `tests/scale.test.mts` (23 KB)

**Problem.** The suite that proves the product's core differentiator — 1,000
businesses in one trade, every design unique, the closest pair far below the
regeneration threshold — had no npm script and was absent from `test:all`. It is
cited as evidence in `SCALE-PROOF-2026-10-07.md`, so it had been run by hand at
some point; nothing would run it again. A quality gate nobody runs is a
document, not a gate.

**Solution.** `npm run test:scale` added **and wired into `test:all`**, which is
what makes it a gate rather than an accessible file. The suite is pure (no
server, no database, no model) and its `COUNT`/`SAMPLE` are
environment-overridable, so `COUNT=100 npm run test:scale` is a fast check and
the default is the full proof — 1,000 businesses, 1,000 distinct designs, 39 ms
per site, 46.7 s on this machine.

### M3. A 1.4 MB patch of already-merged work was committed

**File:** `GMB-PATCH-e67100a3.patch`

**Problem.** A 142-file diff of commits that were already on `main`. It also
re-added `freemodels-api (1).json`, a duplicate of the config deleted in M2-ish
circumstances above — applying it would undo work. It was being copied into the
standalone build along with everything else.

**Solution.** Deleted. `.gitignore` now refuses `*.patch`, `*.diff`, `*.bundle`
and (outside `public/`) `*.zip`, so the next one cannot be committed by
accident.

## F. UI, responsive behaviour and accessibility sweep

The brief asks for a designer's eye as well as an engineer's. This is the sweep
that was run, and its honest result: this area is in better shape than the
build pipeline was, so it produced two changes rather than twenty. Findings
below are what was checked and what was found — the "clean" rows are the point
of the table, not padding.

| Checked | How | Result |
|---|---|---|
| Fixed-width elements causing horizontal scroll | `grep` for `w-[NNNpx]` across every view, then reading each hit in context | 20 hits, **all inside an `overflow-x-auto` or a deliberately scaled device preview** (`max-w-[420px]` mobile / `max-w-[820px]` tablet / full-width desktop in the builder; `1100×1100` origin-scaled concept thumbnails in onboarding). No accidental page-level overflow found. |
| Tables on a phone | every `<table>` in the views | Each one is wrapped in `overflow-x-auto`; the wide ones carry an explicit `min-w-[…]` so columns keep their proportions instead of crushing (leads switches from a card list to a table at `md`). |
| Images | every `<img>` in `src/components` and `src/app` | 18 tags, every one has a real `alt` (decorative art uses `alt="" aria-hidden="true"` deliberately, carousel images fall back through alt → caption). Tenant-supplied remote URLs are intentionally not `next/image` — documented in `site-image.tsx`. |
| Interactive elements | `aria-label` coverage, `type="button"`, icon-only buttons | The console's shared primitives (`console-ui.tsx`) already do this properly: `DeleteConfirm` names what it deletes (`aria-label="Delete {name}"`), `FormError` uses `role="alert"`, `EmptyState`/`LoadingRows` exist so no screen ships bare. |
| Form validation surfacing | read `FormError` and its call sites | Validation is shown in-flow next to the form, not only as a toast — the comment in `console-ui.tsx` explains why (a toast is missed on a phone with the keyboard up). |
| Empty / loading / error states | grep every tab for the three | Present in all fourteen dashboard tabs and every admin tab (`EmptyState`, `LoadingRows`, `ErrorState` with `onRetry`). |
| Chart layout stability | the change made in M1 | The lazy components render a skeleton of the exact container height (`h-64`, `h-44`, `h-full`) before recharts arrives, so nothing reflows when it loads. |
| Browser history / deep links | read the console routing | Each tab is a real URL (`/dashboard/leads`), validated server-side; an unknown tab is a 404 rather than a silent Overview; legacy `/#/dashboard` links are still translated in `app-store.ts`. |

**Changed by this pass:** the two chart call sites (M1), which also removed the
one hard-coded colour literal that was duplicated between a legend and a chart,
replacing it with the equivalent Tailwind classes that cannot drift apart.

**Not verified here:** pixel-level rendering. Playwright cannot download its
browsers in this environment, and there is no substitute for looking at it. The
claims above are from reading the markup and the CSS, which is how the
fixed-width and overflow findings were reached — they are not a substitute for a
real device pass, and that remains the one recommendation for a human to do.

## G. Checked and found sound — do not "fix" these

Being critical cuts both ways. These were examined specifically because they
look like problems and are not:

- **Tenant isolation.** Every `[id]` route resolves the row with
  `findFirst({ where: { id, businessId } })` before acting
  (`content/[type]/[id]`, `leads/[id]`, `orders/[id]`, `domains/[id]`).
  `requireBusiness` derives the business from the session and never from the
  request. No IDOR found.
- **Sessions.** httpOnly / SameSite=Lax / Secure-in-production cookies, HMAC
  over a payload carrying `tokenVersion`, compared with `timingSafeEqual`, with
  the database value checked on every request so revocation is real.
- **Payments.** Server-computed amounts, HMAC signature verification, a second
  server-side fetch before trusting "captured", ownership cross-checked against
  order notes, idempotent activation keyed on invoice number.
- **Uploads.** Magic-byte sniffing rather than the client's `Content-Type`, SVG
  refused, path-traversal-safe resolution, `nosniff` on the serving route.
- **Rate limiting.** The keys whose purpose is to survive a rotating IP pool are
  counted per subject, not per IP; `clientIp` reads `X-Forwarded-For` from the
  right, so it cannot be forged. The in-memory store is correct for the
  documented single-process deployment and is flagged in `SCALE-AUDIT.md` as the
  thing to move to Redis before scaling out.
- **Public write paths.** The analytics beacon validates event types against an
  allow-list and caps per slug+IP; order tracking needs number *and* phone and
  answers one 404 for both failure modes; lead spam is limited per site.
- **CSV export.** Lead-supplied text is prefixed before it can become an Excel
  formula (`csvCell`).
- **JSON-LD.** Escaped before it reaches `dangerouslySetInnerHTML`.
- **Route guards.** All 95 API routes were enumerated; the only ones without an
  authentication guard are the ones that are meant to be public, and the two
  `/api/internal/*` routes require a timing-safe `INTERNAL_TOKEN` and stay
  *off* when it is unset.

## H. How to verify this pass

```bash
npm ci
npx prisma generate && npm run db:push && npm run seed

npm run lint                 # 0 problems
npx tsc --noEmit             # no output
npm run build                # succeeds offline; ends with "check-standalone: … is clean"

npm run test:scale           # the 1,000-site uniqueness proof
npm run test:all             # unit suites
BASE_URL=http://127.0.0.1:3000 ADMIN_EMAIL=… ADMIN_PASSWORD=… npm run test:api
```

`npm run db:push` and `prisma generate` normally fetch Prisma's native engines
from `binaries.prisma.sh`. That host is unreachable from the sandbox this pass
ran in — the schema is already configured for driver adapters
(`engineType = "client"` + `@prisma/adapter-libsql`), which is the path that
made it work here. This is an environment note, not a change to the app.
